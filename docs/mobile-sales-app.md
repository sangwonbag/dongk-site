# 동경바닥재 모바일 판매 앱 (PWA)

기존 사이트와 동일한 React 화면·Supabase 데이터·주문 API를 재사용합니다. 상품과 가격, 계정, 주문 데이터는 별도 복제하지 않습니다.

## 설치
- 갤럭시 Chrome: 사이트 접속 → 앱 설치, 또는 Chrome 메뉴(⋮) → 홈 화면에 추가
- 아이폰 Safari: 사이트 접속 → 공유 버튼 → 홈 화면에 추가
- 설치 아이콘(192/512 PNG)은 npm run dev 및 npm run build 전에 자동 생성됩니다.

## 주문/결제
기존 /materials → /cart → /checkout → /order-complete → /orders 경로를 그대로 사용합니다. 기존 결제 수단인 계좌이체와 방문결제만 사용하며 카드 PG를 새로 도입한 것은 아닙니다. 주문/인증/결제는 온라인 전용으로, 서비스 워커가 응답을 캐시하지 않습니다.

## 배포 전 확인
- npm run build 성공, 아이콘 192px/512px 크기 확인
- iOS Safari와 Android Chrome에서 설치 후 앱 실행
- 로그인, 상품검색, 상품상세, 수량/금액, 배송옵션, 장바구니, 주문, 주문내역을 테스트 계정에서 검증
- 기존 사이트의 장애는 동일 코드를 공유하는 앱에도 영향을 주므로 별도 점검

앱스토어 또는 플레이스토어 공개를 원하면 향후 Capacitor 포장과 플랫폼별 심사 작업이 필요합니다.

## 사이트·앱 통합 관리자

- 운영 화면은 기존 `/admin` 하나입니다. 별도 앱 관리자 또는 데이터베이스를 만들지 않습니다.
- 관리자/직원 권한으로 모바일 앱에 로그인하면 모바일 하단 메뉴 마지막 항목이 `통합관리`로 바뀌어 기존 `/admin`을 엽니다.
- 상품·단가·노출 여부는 기존 `products`, `categories`, `brands` 데이터를 사용하는 `/admin/products`, `/admin/materials`에서 관리합니다.
- 두 채널에서 접수한 주문은 기존 `orders` / `order_items`에 기록되고 `/admin-orders` 및 `/admin/orders`에서 동일하게 관리합니다.
- 견적 및 문의도 기존 서비스를 그대로 재사용하며, 고객 로그인과 권한 확인도 기존 AuthProvider/AdminRoute에서 처리합니다.
- 웹사이트와 홈 화면 앱은 같은 도메인과 같은 배포를 사용하여 별도 상품 업로드나 별도 앱 배포가 필요 없습니다.
- **유의:** 장바구니는 현재 브라우저 로컬 스토리지 기반이므로 다른 휴대전화/브라우저와 자동 동기화되지 않습니다. 최종 접수된 주문은 서버 DB에서 통합 조회됩니다.
- 상품 검색에는 기존 정적 예비 카탈로그와 클라이언트 캐시도 사용됩니다. 관리자가 단가를 바꾼 직후 반영되지 않는 사례가 있을 수 있으므로 새로고침 및 상품 상세/결제 금액을 확인하세요. 이 변경은 서버측 가격 확정 로직 자체를 수정하지 않습니다.
